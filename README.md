# أداة تسجيل البث (Stream Recorder)

تسجيل من رابط بث مباشر (HLS/DASH/MP4/RTMP) عبر ffmpeg بجودة أصلية بدون إعادة ترميز، مع رفع تلقائي لـ Backblaze B2 وحفظ رابط دائم لكل مباراة، مقسّم على ناديين.

## 1) التثبيت

```bash
cd stream-recorder
npm install
cp .env.example .env
```

افتح `.env` وعبّي:
- `API_KEY`: أي نص سري تختاره (يحمي السيرفر من أي شخص يستخدمه غيرك)
- `CLUB1_NAME` / `CLUB2_NAME`: أسماء الأنديه اللي بتظهر بالواجهة
- `MAX_CONCURRENT_RECORDINGS`: كم تسجيل يشتغل بنفس اللحظة (افتراضي 2)
- `B2_QUOTA_GB`: مساحة B2 التقريبية بالجيجا (لعرض شريط الاستهلاك بالواجهة فقط)
- `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`: تنبيهات تيليجرام (اختياري، اتركهم فاضيين لو ما تبيها)
- بيانات B2 (الخطوة التالية)

## 2) إعداد Backblaze B2 (بدون بطاقة ائتمان)

1. أنشئ حساب مجاني على [backblaze.com/sign-up/cloud-storage](https://www.backblaze.com/sign-up/cloud-storage) (بدون بطاقة)
2. من لوحة التحكم → **Buckets** → **Create a Bucket**
   - النوع: **Private** (تفادي طلب البطاقة الخاص بالـ Public)
3. من نفس صفحة الـ bucket، سجّل قيمة **Endpoint** (مثل `s3.us-east-005.backblazeb2.com`)
4. من القائمة الجانبية → **App Keys** → **Add a New Application Key**
   - اربطه بنفس الـ bucket فقط، صلاحية Read and Write
   - انسخ `keyID` و `applicationKey` **فورًا** (يظهران مرة وحدة فقط)
5. عبّي بملف `.env`: `B2_KEY_ID`, `B2_APPLICATION_KEY`, `B2_BUCKET_NAME`, `B2_ENDPOINT`, `B2_REGION`

> بما إن الـ bucket **خاص (Private)**، الروابط اللي تطلع لك مش دائمة — هي "روابط موقّعة" صالحة لمدة `SIGNED_URL_EXPIRY_DAYS` يوم (افتراضيًا 14 يوم، تقدر تغيّرها بـ `.env`). كل مرة تفتح صفحة "التسجيلات المحفوظة"، السيرفر يولّد لك روابط جديدة صالحة تلقائيًا — فما تحتاج تسوي شي إضافي، بس خلي بالك الرابط اللي تشاركه يُفتح خلال هالمدة.

## 3) التشغيل

```bash
npm start
```

افتح `http://localhost:3000` (أو IP جهازك على نفس الشبكة، أو رابط الـ Tunnel لو تشغّله عن بعد).

أول مرة تفتح الصفحة بيطلب منك API Key — حط نفس القيمة اللي بـ `.env`.

## 4) عن جودة 720p

الأداة تسجّل بـ `-c copy`، يعني تنسخ نفس جودة الرابط اللي تحطه **بدون تغيير** (أسرع وأدق وما يستهلك معالج). فلو تبي تسجيل بجودة 720p تحديدًا:

- إذا مصدر البث يوفر عدة جودات (renditions)، الصق **رابط الجودة 720p تحديدًا** (مو رابط الـ master playlist العام) إذا كان متوفر لك بشكل منفصل.
- إذا عندك رابط واحد فقط وتبي إجبار السيرفر يحوّل لـ 720p دائمًا، قلي وأضيف لك خيار تحويل اختياري (`-vf scale=-2:720`) بالواجهة — بس خلي في بالك هذا يعيد الترميز فيستهلك معالج أكثر ويبطّئ قليلاً حسب قوة جهازك.

## 5) الأمان ضد أنواع الروابط

السيرفر يقبل فقط الروابط اللي تبدأ بـ:
`http://`, `https://`, `rtmp://`, `rtmps://`, `rtsp://`

أي رابط ثاني (مسار محلي، أوامر مدمجة، بروتوكولات غريبة) يُرفض تلقائيًا قبل ما يوصل لـ ffmpeg — عشان ما يصير حقن أوامر (command injection) عبر الرابط.

## 6) النشر على Termux (نفس طريقة مشروعك الثاني)

`.env` صار داخل الزب مباشرة بقيمك الحقيقية كاملة (مو `.env.example` بس) — فما تحتاج `cp` ولا `nano`، بس فك الضغط وشغّل:

```bash
pkg install nodejs ffmpeg
cd ~
rm -rf stream-recorder
unzip /sdcard/Download/stream-recorder.zip
cd stream-recorder
npm install
npm start
# لفتح الأداة من بعيد (مثلاً من جوالك مباشرة أو عبر appcreator24)، شغّل نفق بجهة ثانية:
cloudflared tunnel --url http://localhost:3000
```

> ⚠️ تنبيه أمان: `.env` صار فيه مفاتيحك الحقيقية (API key وB2 keys) مكتوبة صريحة داخل الزب نفسه. لا تسوّي `git init` أو ترفعه لأي مستودع عام وهو فيه — لو تبي تحطه على GitHub لاحقًا، أول شي حط `.env` بملف `.gitignore`.

> **مهم للجدولة:** لو تبي تستخدم ميزة "جدولة وقت البدء" وأنت مو فاتح التطبيق وقتها، لازم السيرفر (`npm start`) يضل شغال بالخلفية على جهازك وقت الموعد — الجدولة تُنفَّذ من داخل السيرفر نفسه، فلو قفلت Termux أو قتلت العملية قبل الموعد، ما راح يبدأ. استخدم `termux-wake-lock` قبل `npm start` عشان أندرويد ما يوقف العملية بالخلفية.

## 7) تحويلها لتطبيق عبر appcreator24

بما إنها ويب أب كاملة (frontend + backend منفصلين)، بس تحط رابط السيرفر (رابط الـ Tunnel أو الدومين) كـ URL بالأداة، وتطلع لك تطبيق WebView يفتح نفس الواجهة. تأكد إن السيرفر شغال باستمرار وقت ما تفتح التطبيق.

## 8) بنية التخزين على B2

كل تسجيل يترفع بالمسار:
```
club1/2026-08-09_1830_ميلان-vs-تورينو.mp4
club2/2026-08-10_2000_match-name.mp4
```

القائمة بالواجهة تُقرأ مباشرة من B2 (بدون قاعدة بيانات منفصلة) — يعني حتى لو أعدت تشغيل السيرفر أو غيّرت الجهاز، التسجيلات القديمة تضل تظهر طبيعي.

## 9) البث المباشر على OK.RU

حقل "رابط RTMP + مفتاح البث تبع OK.RU" بواجهة "📡 بث مباشر + تسجيل" يتغيّر كل مرة (OK.RU ما يعطيك رابط ثابت)، فتحصل عليه من: حسابك بـ OK.RU → **Broadcast** → **Open Application** → تنسخ رابط RTMP + المفتاح والصقهم بسطر وحد بهذا الحقل، مثال:
```
rtmp://vd.trbnr.ok.ru/input/1234567890abcdef
```
لما تضغط "ابدأ البث"، ffmpeg يقرأ من مصدر البث **مرة وحدة** ويخرّج بنفس الوقت لمكانين: HLS محلي (يُستخدم للمعاينة والتسجيل) + دفع RTMP مباشر لـ OK.RU. لو الحقل فاضي، البث يشتغل محليًا بس بدون دفع خارجي. لو تبي قيمة احتياطية تلقائية (بدل ما تلصقها كل مرة)، تقدر تعبي `OKRU_RTMP_URL` بـ `.env` وتُستخدم فقط لو الحقل بالواجهة تُرك فاضي.

## 10) التسجيل يُرفع مباشرة أول بأول (بدون كتابة ملف فيديو على جهازك)

خرج ffmpeg (mp4 مجزّأ/fragmented) يتحول فورًا لأنبوب (pipe) يُرفع لـ B2 كـ multipart upload من أول ثانية تسجيل — ما فيه أي ملف فيديو كبير يتكتب على قرص جهازك أثناء التسجيل ولا حتى مؤقتًا، فما يعلّق الجهاز أو يعبّي مساحته حتى لو التسجيل طويل. الرفع يكمل أول بأول أثناء التسجيل نفسه، ولما تضغط "إيقاف"، بس آخر أجزاء بسيطة (آخر ثواني) تنتظر تكمل رفعها.

> ملاحظة توافق: بما إن الملف mp4 مجزّأ (fragmented) بدل الصيغة العادية، أغلب المشغلات الحديثة (المتصفح، VLC) تشغّله عادي، لكن بعض البرامج القديمة جدًا قد ما تقرأ مدة الفيديو فورًا عند الفتح (يظهرون المدة أثناء التشغيل بدل ما يكون معروف من البداية) — هذا طبيعي وما يأثر على جودة أو اكتمال الفيديو.

## 11) فصل البث المباشر عن التسجيل (بث على Render + تسجيل على ترمكس)

عشان تفادي حرارة/تعليق الجوال وقت استخدام اللوقو، تقدر تفصل الشغل بين مكانين بنفس الكود بدون أي تعديل:

- **نسخة على Render (مجانية، بدون بطاقة):** تستخدم منها بس زر "بدء البث" — تحط اللوقو وتدفع RTMP لـ OK.RU. المعالجة الثقيلة (الترميز) تصير هناك، مو بجوالك.
- **نسخة بترمكس (نفس اللي عندك الحين):** تستخدم منها بس زر "تسجيل" — بدل ما تحط رابط المصدر الأصلي، تحط رابط HLS تبع نسخة Render (يطلع لك بالشكل: `https://اسم-تطبيقك.onrender.com/live/club1/stream.m3u8`). بما إن الفيديو جاي من Render أصلاً فيه اللوقو، جهازك يسجّله بـ "نسخ" بس (بدون معالجة) — خفيف جدًا على المعالج والحرارة.

### خطوات نشر نسخة Render:

1. سجّل حساب مجاني على [render.com](https://render.com) (بدون بطاقة).
2. ارفع نفس مجلد المشروع لمستودع GitHub خاص (Private repo) — أو اربطه مباشرة لو تفضل طريقة ثانية بلوحة Render.
3. من لوحة Render: **New → Web Service** → اختر المستودع.
4. Render يكتشف `Dockerfile` تلقائيًا (موجود بالمشروع) ويستخدمه — ما تحتاج تحدد Build/Start Command يدويًا.
5. أضف متغيرات البيئة التالية بلوحة Render (تبويب Environment):
   ```
   API_KEY=نفس-المفتاح-اللي-تستخدمه-بترمكس
   CLUB1_NAME=اسم-النادي-الأول
   CLUB2_NAME=اسم-النادي-الثاني
   ```
   (ما تحتاج تحط مفاتيح B2 ولا تيليجرام هنا — هذي النسخة بث بس، ما تستخدم التسجيل).
6. اضغط **Deploy**. أول نشر ياخذ كذا دقيقة (يثبت ffmpeg داخل الصورة).
7. بعد ما يخلص، Render يعطيك رابط ثابت شكله `https://اسم-تطبيقك.onrender.com`.

### طريقة الاستخدام اليومية:

1. افتح رابط Render، حط رابط البث المصدر + اللوقو (لو تبيه) + رابط OK.RU، واضغط "ابدأ البث".
2. افتح تطبيقك بترمكس (زي ما تسوي دايمًا)، وبدل رابط المصدر الأصلي بنموذج "تسجيل"، حط: `https://اسم-تطبيقك.onrender.com/live/club1/stream.m3u8` (بدّل `club1` حسب النادي اللي بدأت بثه).
3. اضغط "ابدأ تسجيل" بترمكس — بيسجل ويرفع B2 زي ما هو، بس بدون أي معالجة إضافية لأن اللوقو محطوط عليه أصلاً.

> ملاحظة: الخطة المجانية بـ Render "تنام" بعد 15 دقيقة بدون طلبات. أول ما تدخل الرابط بعد فترة سكون، انتظر 30-60 ثانية قبل ما تضغط "ابدأ البث" عشان يصحى كامل.

## 12) أشياء مهمة تعرفها

- **الحماية من نسيان الإيقاف:** لو نسيت توقف التسجيل، يوقف تلقائيًا بعد `MAX_RECORDING_HOURS` (افتراضيًا 5 ساعات) — إلا لو حددت وقت إيقاف مجدول، فوقتها يوقف بالساعة اللي حددتها.
- **تسجيل متزامن:** حتى `MAX_CONCURRENT_RECORDINGS` تسجيل بنفس اللحظة (افتراضيًا 2) — سواء لنفس النادي أو موزعة بين الناديين. أي محاولة زيادة عن الحد تُرفض برسالة واضحة.
- **جدولة اختيارية:** عند بدء تسجيل جديد، تقدر تحدد "وقت بدء" و"وقت إيقاف+رفع" — لو تركتهم فاضيين يشتغل يدوي زي المعتاد (ابدأ الآن، أوقف بالزر).
- **تبويب "نظرة عامة":** يعرض حالة الناديين الاثنين بشاشة وحدة (شغال/مجدول/يرفع) بدون ما يأثر على تبويباتهم المستقلة.
- **الإيقاف صار فوري:** ضغط "إيقاف" يرجع استجابة فورية، والرفع يكمل بالخلفية بحالة "جاري الرفع" منفصلة — ما يعلّق الواجهة.
- **الحذف الحقيقي:** زر "حذف" الحين يتأكد فعليًا إن الملف اختفى من B2 (مو بس يفترض النجاح) — لو فشل الحذف الفعلي يرجع لك خطأ واضح بدل ما يسكت.
- **تنبيهات تيليجرام:** اختيارية، لو عبيت `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` بـ `.env` بترسل لك رسالة عند بدء التسجيل، نجاح الرفع (مع الرابط)، أو أي خطأ.
- **مساحة B2 المجانية:** 10GB تخزين تقريبًا، ويظهر شريط استهلاك حي أعلى الواجهة. بجودة 720p، الساعة تقريبًا 0.7-1GB حسب البِت ريت — راقب الاستهلاك أول أسبوعين وعدّل `B2_QUOTA_GB` لو احتجت.
